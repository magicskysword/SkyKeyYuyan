# SkyKeyYuyan 恢复与词频存储

运行时恢复以保留有效编辑状态为基础。语言计算、正文写入和词频记录具有分别可识别的执行结果，恢复流程据此继续操作。

## 初始化结果

首次初始化失败时结束本次尝试，释放该尝试取得的资源，返回失败模块、阶段和原因。注册配置保留，调用者修正后可再次初始化。

异步初始化被取消时执行对应清理，并返回取消结果。运行期间新增语言的资源准备独立进行，失败通过该语言的初始化结果报告，已就绪模块和会话继续服务。

初始化失败的运行时实例不会取代全局默认实例。用户词频预加载失败不影响初始化结果，按[词频加载](#词频加载)中的失败规则处理。

## 检查点

语言检查点为不可变对象，保存：

- 引擎标识和组合状态格式版本。
- 原始拼写、已选片段与未转换范围。
- 组合光标及回退历史。
- 恢复当前组合所需的语言设置与资源关联信息。

字典和索引由模块共享。检查点通过明确的状态对象表达，恢复时由对应引擎检查版本和资源兼容性。

会话在可能改变组合状态的操作前取得有效检查点，并保留最后一次成功操作后的状态。正文已生效时，恢复使用与该事实一致的提交后状态；正文尚未生效时，可以回到提交前状态。

## 故障处理

| 故障 | 自动恢复 | 持续故障后的处理 |
| --- | --- | --- |
| 当前候选查询失败 | 保留组字，针对仍有效的查询自动重试一次 | 进入字面输入状态，保留编辑能力 |
| 引擎处理失败 | 创建新实例，恢复最近有效检查点，重试当前操作一次 | 进入字面输入状态 |
| 检查点恢复失败 | 返回恢复原因，保留运行时最近有效的展示和输入数据 | 进入字面输入状态 |
| 明确尚未执行的文本写入失败 | 根据适配结果决定是否安全重试 | 保留待提交内容并报告错误 |
| 文本写入结果未知 | 重读目标并核对操作执行状态 | 保留宿主正文和待处理内容，交由明确的后续处理 |
| 用户词频加载失败 | 自动重试一次 | 当作空存档处理，之后的保存覆盖原有数据，并报告诊断 |
| 词频存档失败 | 保留待保存数据，返回存储结果 | 宿主可重新保存 |

一次恢复流程最多自动重试一次。重建实例同时推进引擎代次，先前实例的异步结果因此失效。恢复成功后在原会话内继续操作，并向宿主提供恢复诊断。

## 字面输入状态

恢复失败后，输入界面保留正文、已选片段和原始拼写，允许继续编辑和保存。例如“你好 + shijie”可作为“你好shijie”继续输入。

默认面板保持完成、取消、删除和语言切换操作可用，并提供“重试转换”。语言切换使用当前会话已配置且可用的语言实现。

显式重试转换创建一次新的恢复请求，以当前保留的已选片段和原始拼写为依据，保留字面输入期间产生的编辑。恢复成功后整体替换转换状态；失败时继续保留当前输入及错误信息。

## 操作执行记录

会话为操作分配单调递增的序号，与会话标识共同确定其身份。记录包含语言状态处理结果、目标编辑状态、选择记录处理状态及是否已发布完成通知。

| 执行状态 | 恢复规则 |
| --- | --- |
| 尚未生效 | 可在恢复有效检查点后重试 |
| 已确认生效 | 保留已有结果，继续尚未完成的步骤 |
| 生效情况未知 | 先查询或重读权威状态，再决定后续操作 |

正文、词频与事件通知分别记录状态。例如，正文写入已经成功但后续宿主回调抛出异常时，已写入正文保持有效，恢复只处理尚未完成的内部步骤。

原框插入操作不能仅凭返回异常判断为未写入。适配器优先提供本次操作的已知结果；结果不明确时，读取当前目标正文和版本，保留待处理输入供宿主或用户确认。

若确定发生了宿主外部正文修改，则按照[会话与文本编辑](session-and-editing.md)的外部变化规则结束会话，保留宿主最新内容。

## 选择记录

一次成功的候选确认生成稳定的选择记录标识。恢复过程重用该标识，词频服务对该次选择累计一次。

| 情况 | 词频行为 |
| --- | --- |
| 浏览候选 | 调整候选位置 |
| 选择已有词条 | 累计该词条 |
| 选择已有整句词条 | 累计该整句词条 |
| 选择由已有词条组成的句子 | 按候选提供的组成词条累计 |
| 选择“你好”后正文只接受“你” | 累计“你好” |
| 长度截断到零 | 已成功产生的选择记录仍以原词条为统计对象 |
| 同一操作恢复或重试 | 沿用原选择记录，维持一次累计 |

原框模式的有效选择直接进入用户词频。草稿模式将记录保存在会话暂存区，完成保存时合并，取消、外部修改导致结束、目标失效或运行时释放时丢弃暂存记录。

成功保存草稿后，全文长度截断不改变所选词条的统计身份。

## 用户和词条身份

持久化命名范围由用户标识、语言标识和稳定词条标识组成。宿主提供用户标识，设备号和玩家槽位用于输入路由。

相同用户的会话共享累计词频，不同用户的数据独立。用户词频服务在进程内按用户共享，不属于某个运行时实例；同一用户在多个实例中的选择累计到同一份数据，存档修订号统一递增，不会互相覆盖。宿主更新自定义词条权重时保留该词条标识，使已有词频继续生效。

## 词频加载

| 用户 | 加载时机 |
| --- | --- |
| 默认用户 | RuntimeOptions 指定，初始化时预加载；SessionOptions 省略用户标识时使用 |
| 预加载用户 | RuntimeOptions 列出，初始化时预加载 |
| 其他用户 | 打开会话时不等待，在后台加载 |

后台加载期间会话立即可用，候选先按基础权重排序，加载完成后刷新。加载期间产生的选择记录保留在内存中，加载完成后合并。

同一用户和语言的并发加载共享一个完成结果。读取尚未结束时的保存请求等待该结果及内存增量合并，然后获取串行写入权并生成完整快照。

加载失败时自动重试一次。重试仍失败时当作空存档处理，之后照常保存，覆盖该用户原有的存档数据，避免一次读取失败后该用户无法再存档。加载失败和覆盖均通过诊断报告。预加载失败同样按此规则处理，不影响初始化结果。

## Provider 数据契约

Provider 读写结构化词频快照，包含用户、语言、数据格式版本、存档修订号及词条计数集合。Provider 负责实际序列化和存储介质。

存档 Provider 在进程内只配置一次，由共享的用户词频服务使用：宿主在创建第一个运行时实例前设置，或由第一个实例的 RuntimeOptions 带入，之后的实例沿用。Provider 由宿主创建和释放，运行时从不调用其 Dispose。

同步和异步读写返回一致语义的结果。一次保存接收指定修订的完整数据，因此重试同一修订具有相同的目标存储状态。

同一用户和语言的保存串行执行。保存开始后产生的新选择属于更新修订；较旧保存完成时，仅清除其已经覆盖的待保存状态，更新修订继续保留。

数据格式以版本号管理。读取时根据支持的版本范围解释数据，需要转换时返回明确的迁移结果或失败原因。

## Unity 默认存储

Unity 默认 Provider 使用 PlayerPrefs，将结构化快照序列化为可存储记录，并按需要分块组织词条数据。键名按用户、语言和数据版本划分命名范围。该 Provider 由 Unity 转换核心以宿主身份创建和释放。

初始化阶段预加载默认用户及指定用户的存档，其他用户在打开会话后加载；输入期间在内存累计；会话结束时批量保存。宿主可接管自动保存时机，并显式请求保存待处理数据。

Unity 的 PlayerPrefs.Save 会写入修改过的偏好数据，实际调用可能产生耗时，因此默认流程在会话结束等保存时机集中执行。该调用也可能刷新宿主其他已修改偏好，集成时应统一安排保存时机。[Unity PlayerPrefs.Save 文档](https://docs.unity3d.com/2020.3/Documentation/ScriptReference/PlayerPrefs.Save.html)

异步存储入口通过 Unity 执行上下文调用需要主线程执行的 PlayerPrefs 操作；数据准备可以在适当上下文完成。异步接口表达完成和取消语义，底层写入耗时纳入性能验证。

## 保存结果与会话结果

正文编辑成功和词频保存成功分别报告。保存失败时保留内存中的待保存修订，宿主可按自己的存档流程重试。

运行时实例结束时自动保存待写修订：被替换后最后一个会话结束时，或宿主显式调用 Dispose 时。仅靠 GC 回收不会触发保存，因此实例在交给 GC 之前先完成保存。保存失败通过诊断报告。

会话完成通知包含当时的存档状态。后续异步保存结果通过存储完成结果或诊断交付，正文完成事件保持一次。

FrequencyService.Shared 为运行时共用的进程服务，ConfigureStore 在首次使用前配置 Provider。独立宿主也可以直接使用 FrequencyService 处理结构化存档。FrequencyStoreResult 提供用户、语言、读写结果、快照及 Pending 状态。

同步保存遇到正在进行的加载或写入时，安排后台保存并返回 Pending。运行时释放后，共享服务继续完成这些读写。宿主在释放存档 Provider 或结束进程前调用 SaveFrequenciesAsync，等待待保存数据写入完成。RuntimeOptions.AutoSaveFrequencies 控制自动保存时机。

## 恢复诊断

诊断包含错误阶段、关联模块、会话与操作标识、恢复次数、结果以及调用者可理解的原因。表现层据此展示处理中、已恢复、字面输入或需要处理的文本状态。

预期的取消、目标生命周期结束与用户主动语言切换按各自状态转换处理。恢复流程服从会话当前的有效生命周期。
