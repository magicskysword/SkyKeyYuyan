# SkyKeyYuyan 性能基准

软件版本为 0.1.0，语言数据为 2026.10.3。本次基准使用完整中文 263274 条读音记录、英语 274937 条词条，以及基础英语和韩语模块。

## 测量方法

在生成数据后运行：

```powershell
node scripts/benchmark.mjs
node scripts/check-performance.mjs --player-report artifacts/Reports/player-package-mono.json
```

第一条命令使用 Release 构建的独立 .NET 宿主，生成 `artifacts/Reports/performance.json`。报告包含机器、运行时、资源版本、原始毫秒样本、分配量和各代 GC 次数。第二条命令按 `scripts/benchmark/budgets.json` 检查相同环境的结果，输出 `performance-budget.json`；Player 报告由 UPM 安装验证生成。

初始化分别测量进程首次同步调用和随后新实例的异步调用，两次均重新解析资源和建立索引。操作系统文件缓存不在测量中清空。词典稳态内存取完整 GC 后的托管堆增量；进程峰值工作集还包含初始化、JIT 和其余基准的临时内存。

候选查询先预热二十次，再采样二百次，计入后台调度到查询返回的时间。双查询同时请求中文 `nihaoshijie` 和英语 `compu`，延迟按一对查询全部完成计算。反馈测量在宿主线程投递逐字符输入，记录对应组字首次通过 `StateChanged` 发布的时间；单人采样三百次，双人交替输入采样六百次。每个词完成候选查询并确认“很”，反馈分配量也包含这些候选和确认步骤。

反馈数据描述托管运行时的状态更新，不含 UI 排版、渲染或显示刷新。长历史基准保存一万个字符的历史，分别测量捕获、恢复及恢复后的首次快照生成。内存 Provider 的读写和 Unity PlayerPrefs 的持久化分别记录。

## 基准结果

测量日期为 2026-10-18。机器为 Windows 11，系统构建 26200，Intel Core i7-13700KF，二十四个逻辑处理器，约 64 GiB 内存。托管宿主使用 .NET 10.0.11、X64、Workstation GC；Player 使用 Unity 2022.3.62f3 Windows Mono，启用高级托管裁剪。

| 指标 | 结果 |
| --- | --- |
| 首次同步初始化 | 667 ms |
| 新实例异步初始化 | 617 ms |
| 完整词典稳态托管增量 | 107.6 MiB |
| 基准进程峰值工作集 | 237.3 MiB |
| 一万个字符历史的托管增量 | 1.07 MiB |
| 检查点捕获及恢复 P95 | 各小于 0.001 ms |
| 恢复并生成长组字快照 P95 | 0.772 ms |

| 输入或查询 | 中位数 ms | P95 ms | P99 ms |
| --- | --- | --- | --- |
| 中文 `n` | 0.899 | 1.157 | 1.333 |
| 中文 `hen` | 0.177 | 0.274 | 0.316 |
| 中文 `nihaoshijie` | 0.136 | 0.216 | 0.300 |
| 中文 `zhonghuarenmingongheguo` | 0.209 | 0.359 | 0.484 |
| 中文 `nihaoshijiewoshizhongguoren` | 0.285 | 0.469 | 0.550 |

| 双人状态反馈 | 0.006 | 0.035 | 0.049 |

短前缀会遍历较大的候选集合。中文 `n` 与英语 `c` 的查询平均分配约为 9.9 KiB 和 6.3 KiB；完整分配与 GC 记录保留在原始 JSON 中。

优化前的同机基准使用相同数量的词条。完整词典稳态增量由 184.2 MiB 降至 107.6 MiB，首次初始化累计分配由 813.2 MiB 降至 271.2 MiB。中文 `n` 与英语 `c` 的查询平均分配原为 2505.0 KiB 和 2288.4 KiB，P95 分别为 5.116 ms 和 8.745 ms。

PlayerPrefs 各规模连续执行五次保存和读取，计入首次调用，P95 对应这五次的最大样本。所有调用都在 Unity 主线程执行，保存包含 `PlayerPrefs.Save()`。

## 版本预算

0.1.0 的预算以以上机器和运行时为比较环境，检查器会核对环境与数据版本。其他机器可先生成测量报告，再建立对应环境的预算。

| 指标 | 上限 |
| --- | --- |
| 初始化 | 1250 ms、累计分配 384 MiB |
| 词典稳态托管增量 | 144 MiB |
| 候选查询 P95 | 4 ms |
| 单次查询平均分配 | 256 KiB |
| 托管状态反馈 P95 | 2 ms |
| 连续输入平均分配 | 100 KiB / 输入字符，包含查询和每词确认 |
| 一万个字符历史增量 | 2 MiB |
| 检查点捕获、恢复及首次快照 P95 | 2 ms |
| PlayerPrefs 单次主线程读写 P95 | 20 ms |

本次托管与 Player 联合预算的五十七项检查全部通过。持续集成生成自身环境的测量报告；环境明确匹配时使用预算检查器执行门禁。

## Unity Player 查询测量

Windows Mono Player 新建中文与英语模块，异步加载完整词库耗时 898 ms，托管堆增量约 109.1 MiB。资源由已经工作的宿主 Provider 提供。查询预热十次、采样六十四次，在后台任务完成处计时，避免将主线程下一帧的调度间隔计入耗时。

| 查询 | 中位数 ms | P95 ms |
| --- | --- | --- |
| query/zh-Hans/n | 0.707 | 1.017 |
| query/zh-Hans/nihaoshijie | 0.268 | 0.335 |
| query/en/c | 1.430 | 1.716 |
| query/en/compu | 0.037 | 0.053 |

Player 查询 P95 预算为 8 ms，新模块加载预算为 2000 ms 和 160 MiB 托管堆增量。运行记录保存在 `player-package-mono.json`。
