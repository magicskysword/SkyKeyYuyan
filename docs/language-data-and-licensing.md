# SkyKeyYuyan 语言数据与许可

语言资源在构建阶段转换为纯 C# 引擎可加载的数据。运行时通过资源 Provider 读取已安装资源，语言包同时提供词典、必要规则和平台无关键盘布局。

## 初始数据来源

| 数据 | 采用范围 | 用途 | 来源声明 |
| --- | --- | --- | --- |
| jieba | jieba/dict.txt | 中文词条与基础词频权重 | [MIT 许可](https://github.com/fxsjy/jieba/blob/master/LICENSE) |
| phrase-pinyin-data | 基础 pinyin.txt | 中文词语读音 | [MIT 许可](https://github.com/mozillazg/phrase-pinyin-data/blob/master/LICENSE) |
| an-array-of-english-words | 英语单词数组 | 英语前缀匹配词表 | [MIT 许可](https://github.com/words/an-array-of-english-words/blob/master/license) |
| SKY 维护数据 | 常用单字、读音修订、键盘布局及必要补充 | 完善覆盖与语言输入体验 | 项目 MIT 声明 |

中文词条和词频来自 [jieba 词典](https://github.com/fxsjy/jieba/blob/dafc73425e618c1a0d562f84362b46bedf579bdb/jieba/dict.txt)，读音来自 [phrase-pinyin-data 基础文件](https://github.com/mozillazg/phrase-pinyin-data/blob/cee0ed6e6e4898580cafd2bd5e3723e20b214aa0/pinyin.txt)。数据构建清单明确记录采用文件和来源版本。基础拼音文件的生成范围可对应查看[上游构建规则](https://github.com/mozillazg/phrase-pinyin-data/blob/master/Makefile)。

英语词表提供小写单词列表，来源说明指向 Letterpress 词表。Letterpress 上游采用 CC0 声明。SKY 使用英语列表建立前缀索引，基础排序权重由自身数据配置提供。[英语列表说明](https://github.com/words/an-array-of-english-words/blob/master/readme.md)、[Letterpress 来源与声明](https://github.com/lorenbrichter/Words)

## 词条模型

| 字段 | 说明 |
| --- | --- |
| 词条标识 | 跨数据构建稳定的身份，用于词频和更新 |
| 语言标识 | 中文、英语等语言命名范围 |
| 输出文本 | 实际候选输出 |
| 匹配拼写 | 中文音节序列或英语前缀匹配文本 |
| 基础权重 | 静态词典提供的排序依据 |
| 来源标识 | 对应构建来源清单 |
| 数据修订 | 该条目所属资源数据版本 |

一个中文词条可以具有多个读音条目，读音身份分别保存。相同语言、文本和读音可以合并为统一候选身份。

稳定词条标识由持久化映射表管理，保持已有条目在排序、过滤和重新构建后的身份。资源升级时保留词频可继续引用的映射关系。

中文与英语的映射分别保存在 `data/manifests/chinese-identities.tsv` 和 `english-identities.tsv`。新条目领取递增标识，既有和暂时移除的条目仍保留其原标识。来源版本及采用文件由 `sources.json` 固定。

宿主自定义词组采用相同逻辑字段，词条定义与用户选择次数分别管理。

## 中文资源构建

构建流程先读取词条和读音，再形成面向输入法的匹配数据：

1. 解析源文件，记录条目来源和基础权重。
2. 对拼音执行规范化，保留可区分元音和多音关系所需信息。
3. 优先匹配明确的词语读音；补充常用单字和经过核对的读音规则。
4. 合并同一词语读音的数据，生成稳定标识映射。
5. 生成音节、词条和候选查询所需索引。
6. 执行覆盖、读音、候选和回退用例，导出资源及质量报告。

词语读音和单字读音分别验证。候选构建使用明确的匹配读音，覆盖报告区分可解析记录、可查询词条及已经验证的常用输入样本。

单字读音从已对齐的词语读音提取并保留多音关系。缺少整词读音时，仅在每个字的无声调读音均唯一的情况下组合读音。其余条目进入缺失读音报告。质量报告输出到 `artifacts/Reports/language-data.json`。

常用字回归样本包含“啊”“您”“吨”“很”等；多音词样本覆盖“银行”“行为”等不同词语中的读音。整句验证同时检查转换文本、消耗拼写和组成词条身份。

## 英语和韩语资源

英语构建读取词表并规范化匹配键，生成前缀查询索引。原始输入的大小写由引擎保留，词典匹配和显示形式分别处理。

英语基础权重、宿主自定义权重与用户选择次数分开存储和评估。前缀用例覆盖单词完整输入、候选接受、原样提交和补全开关。

韩语模块提供现代两套式映射、组合规则及默认布局。规则资源与引擎版本一起发布，通过组合和回退用例验证。

## 资源清单和加载

每份资源清单包含：

- 资源标识、语言标识、数据版本及格式版本。
- 引擎可读取的格式版本范围。
- 词条、匹配索引、布局等资源位置和数量信息。
- 来源记录、版权条目及构建工具版本。

资源格式通过版本号和可读取版本范围判断兼容。加载器检查必要段、条目结构和索引范围，错误通过初始化结果返回。

核心资源接口提供同步和异步读取能力。独立 .NET 宿主映射到自己的文件或内存资源，Unity 适配映射到随包安装的资源。语言引擎获得稳定的数据视图后创建会话实例。

词典读取器按行解码 UTF-8，并检查列数、词条身份和权重。规范化后的不可变词条可由基础词库与当前视图共享。基础词条身份直接取自有效词库，宿主词条另保留稳定身份映射；旧数据视图继续持有自己的索引和词条。中文音节边界在带显式分隔符的查询中按需检查。

## 资源升级

数据构建版本与运行时库版本分别记录。引擎声明可读取的格式范围，同一可读格式内的数据更新可沿用加载实现。

自定义词条在运行时更新时推进词典版本，查询结果按照对应版本接纳。共享索引通过完整的新视图发布，使正在使用旧视图的查询能够完成或被取消。

## 数据发布记录

每次数据发布记录采用文件、来源地址、来源版本、许可、转换工具版本、修订数量和质量报告。发布资源与对应清单、整合声明一起进入 NuGet 和 UPM 构建流程。

数据质量报告列出常用字覆盖、词语读音样本、无匹配读音条目、候选排序样本和资源体积。输入质量与结构检查分别呈现，便于定位后续修订。
